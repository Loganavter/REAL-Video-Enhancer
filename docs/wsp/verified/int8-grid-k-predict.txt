# Can the best grid clamp K be predicted from the weights? No - five statistics, none separates

Measured 2026-11-20 (local), probe `scripts/grid_k_predict_probe.py`, raw `logs/grid-k-predict/rows.json`,
targets from `logs/grid-k/ladder.jsonl` (22 models, six K values each).

## The question, and why it is worth a page

The start-up pick (`RVE_INT8_GRID_K=auto`) builds the body at K=1..4, scores each on held-out frames and keeps
the winner under a 2x guard. It costs about 3 s on top of a 6.5 s start-up. If the winner could be read off the
weights, that cost disappears.

The bar is set by two earlier results:

- the calibration grid's dynamic range (max/median of the per-channel maxima) does **not** separate the models
  that improve from the ones that do not - rescued spreads 2.71-6.93, damaged 4.25-4.55;
- the two first-order terms move the same way for **every** model (input quantisation error 2.7-3.9x better
  under per-channel, weight error 1.20-1.40x worse), so the sign is decided by how each model amplifies a
  perturbation, not by either term's size.

## What was tried: four weight-only statistics

Computed per model from the state dict alone - no forward pass, no calibration maxima:

| statistic | what it would capture |
|---|---|
| `row_cv` | coefficient of variation of the per-output-channel weight energy: are a few filters dominant |
| `row_spread` | max/median of the same: the same question with a heavy-tail reading |
| `out_spread` | max/median of the per-input-position energy: does the layer read a narrow set of taps |
| `log_cond` | log10 of the median condition number of the folded weight matrix: does the layer amplify error |

The split is the one the pick's guard uses: **movers** are the 14 models where some K beats K=2 by at least 2x,
**stayers** are the 8 where it does not (including the three that tie at 1.00x and Epsilon at 1.44x).

## Result: every statistic overlaps

```
row_cv      movers 0.074 .. 0.344   stayers 0.106 .. 0.300   OVERLAP
row_spread  movers 1.22  .. 1.643   stayers 1.196 .. 1.546   OVERLAP
out_spread  movers 1.561 .. 2.839   stayers 1.736 .. 2.404   OVERLAP
log_cond    movers 0.50  .. 0.77    stayers 0.52  .. 0.67    OVERLAP
```

The movers' ranges contain the stayers' ranges in all four cases, and not marginally: a mover reads `row_cv`
0.074 while a stayer reads 0.300, and the reverse holds for `out_spread`. With five statistics tried (these four
plus the calibration spread) and no separation in any, the honest conclusion is that the property that decides K
is not a summary of the weights - it is how the quantisation error propagates through sixteen layers to a
thresholded picture statistic, which is what the sweep measures directly.

## What a predictor would need, and why it is not worth building now

The measurement that would capture amplification is a per-layer ablation (quantise one layer, leave the rest
fp16, read the gate) - 16 x 6 x 3 forwards per model, minutes each, i.e. **more expensive than the sweep it would
replace**, and only valid for the model it was run on. That is the same shape as the earlier finding that the
error's sign is set by amplification rather than by either term: the predictor would have to model the amplifier,
and the amplifier is the network.

So the answer to "can we know K without the 2-4 s" is **no, not from the weights**, and the sweep stays. What
would change the answer: a cheap proxy for per-layer sensitivity, or a population large enough that a learned
rule over weight statistics generalises - with 22 models and a 2x guard, neither is available.

## What this does not say

- Four statistics are not "all possible statistics". They are the ones that follow from the two mechanisms
  already measured (weight folding, grid resolution); a predictor built on something else would have to be
  argued from a different mechanism, not from more of the same.
- The targets are three-frame smoke tests. A model sitting at 1.4x (Epsilon) could cross the 2x guard on a
  larger sample, which would move it from stayer to mover - the split itself is not stable at the boundary.
- The pick's 3 s is measured on one model at 1080p; it scales with the number of candidates and the frame size,
  not with the model.
