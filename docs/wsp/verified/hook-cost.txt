# The calibration hooks cost 722 ms a frame, and neither of the two obvious causes is the cause

Measured 2026-11-17 on the same model, frames and interpreter as the probe.

| configuration | ms/frame |
|---|---|
| forward, no hooks | 158.0 |
| forward with the shipped hooks | **879.7** (+721.7, 21.2 ms per hook) |
| the same hooks with the `float()` casts removed | 889.4 |

The hypothesis this tested was that the hooks hold full tensors. They do not: both hook bodies reduce
immediately to a 64-vector, and `_calibrate`'s pre-hook keeps two Python floats. Removing the two
device syncs per conv changes nothing (889 against 880), so the syncs are not the cost either.

What the reduction costs when it is not inside a forward: 2.20 ms for `amin + amax` on a
`[1,64,1080,1920]` fp16 tensor, which is 1.2x its 288 GB/s roofline. Inside the forward the same call on
the same channels_last tensor measures 13.27 ms, and the difference is the conv that produced the
tensor being charged to the hook. **The mechanism is not established**: 34 reductions at 2.2 ms would
be 75 ms, and the measured overhead is 722 ms.

The prize is nevertheless real and bounded: if the hooks cost their isolated 2.2 ms, calibration would
be 24 x (0.158 + 0.075) = 5.6 s instead of 21.1 s, i.e. **-15.5 s on the probe's 45 s**. No fix has
been shown to recover it, and this file does not claim one.
