# The TRT engine is in the probe, and it changes Violet

`probe(..., engine_ref=...)` takes the app's own `UpscalePytorch` and uses it for the fp16 reference -
both in the spread path and in the adversarial path - falling back to the torch model when no engine is
passed.

Feasibility first: the engine built standalone returns `(1,3,2160,3840)` fp16 on cuda and matches the
app's own ungated render at **share 0.0%** (peak 6.3, a rounding difference in the rgb24 decode). So the
engine is reachable and exact; the earlier "plumbing" note was wrong.

| clip | measurement | torch fp16 | TRT engine |
|---|---|---|---|
| Chainsaw | adversarial top-13 | 0.110% | **0.109%** |
| Chainsaw | fp16 control | 0.083% | **0.080%** |
| Violet | depth-2 composition | 0.168% | **0.216%** |
| Violet | own defect | 0.044% | **0.081%** |

On Chainsaw the reference barely matters; on Violet it moves the composition by 29% and the own defect
by 84%. The full fp16 sweeps are 0.07546% and 0.07345%, so the control is still ~6% above them on both
clips - the residual gap is the pair set (the probe re-decides which frames the gate reuses), not the
reference, and `scripts/check_control_ceiling.py` still reports the violation.
