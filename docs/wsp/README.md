# Evidence harness (`scripts/harness/`)

The rule this exists for: **a number is not a scalar.** It is `(value, unit, population, instrument,
config, session, n, statistic)`, and the ten retractions in `RESEARCH-LEDGER.md` all came from filling
the missing fields from memory.

Not documentation of a transfer. Three things:

| what | where |
|---|---|
| the harness | `scripts/harness/` — `core` (records), `run` (three-state probes, artifact parsers), `gates` (A/A, bars, claims, coverage), `astcheck`, `cli`, `migrate` |
| the tests | `backend/tests/test_harness_evidence.py` + `test_harness_redteam.py` — 66, CPU only, no torch |
| the state of the existing findings | `FINDINGS-DEBT-2026-11-16.md` — generated by `harness.migrate`, not written by hand |

The harness was red-teamed on 2026-11-16: 23 ways a false claim could pass were found, 12 are closed
(unit scale, self-declared bars, unknown-formula derived records, unread CLI directives, migration
laundering through its own output, assumed-as-evidence, `NaN`, population-as-mechanism, kind outside the
item hash, synthetic probes, unkeyed sums, cross-session deltas). The 11 that remain are named in
`rve-harness-redteam-residual-2026-11-16`.


## Where a finding goes, now that the notebook is closed

`RESEARCH-LEDGER.md` is 2,400 lines of history and is cited by **line number** from the provenance
tables, so it is not rewritten. It is no longer where anything new goes - a chronological notebook is
what let four superseded verdicts outrank three fresh measurements on 2026-11-17, because markdown has
no notion of a record's lifetime.

New work touches three files, and the index is built from them:

| what | where | shape |
|---|---|---|
| the numbers | `docs/wsp/verified/records/<lane>.jsonl` + `<lane>.txt` | `Record` tuples, checked by `harness.cli check --bars` |
| the conclusion, and its lifetime | `docs/wsp/verdicts.yaml` | `id, lane, status, scope, date, statement, evidence, superseded_by` |
| the prose of a lane | `docs/wsp/history/YYYY-MM-DD-<lane>.md` | free form, linked from the verdict |

Then:

```
python -m harness.cli verdicts                  # refuse an unreadable registry
python -m harness.cli db build                  # rebuild the index from the files
python -m harness.cli db current                # THE entry point: what is true now, by lane
python -m harness.cli db lane int8              # one lane: verdicts + the records behind them
python -m harness.cli db lineage trt-int8-two-pass   # what replaced what
python -m harness.cli db orphans                # records no verdict rests on
python -m harness.cli db stale                  # verdicts whose evidence file is gone
python -m harness.cli db write-block docs/RESEARCH-LEDGER.md   # regenerate the ledger's head
```

The division of labour is the one ML experiment trackers settled on (runs, params/metrics, artifacts, a
queryable store, generated dashboards), with one difference forced by this repo: the **files** are the
source of truth and the SQLite index is a cache that can be deleted and rebuilt from a clone with no
network. `docs/wsp/ledger.db` is gitignored for exactly that reason.

The one rule that makes it work: **a conclusion carries its lifetime.** `status: superseded|refuted`
requires `superseded_by` resolving to a `current` verdict, and a claim citing a non-current verdict is
refused rather than warned about:

```
python -m harness.cli verdicts --cite trt-int8-two-pass
REFUSED: trt-int8-two-pass: status superseded; current verdict is int8-triton-block
```

## Run it

```
PYTHONPATH=scripts python3 -m harness.cli scope                            # what is and is not checked
PYTHONPATH=scripts python3 -m harness.cli env-check                        # do the docs' claims about this host hold?
PYTHONPATH=scripts python3 -m harness.cli below-report "docs/claims-*.txt"  # every @below vs its bar
PYTHONPATH=scripts python3 -m harness.cli check <claims> --records <jsonl>  # claims by key, with coverage
PYTHONPATH=scripts python3 -m harness.migrate "docs/claims-*.txt"         # gate on the existing findings
PYTHONPATH=scripts python3 -m harness.astcheck scripts/harness/*.py       # dead stores, use-before-assignment
python3 -m pytest backend/tests/test_harness_evidence.py -q
```

Checking the whole verified corpus at once (each file pairs with `records/<name>.jsonl`, and the
`--bars` flag matters: two files were failing their own documented command because it omitted it, and
two more cited a `/tmp` records path that a reboot would have taken):

```
for t in docs/wsp/verified/*.txt; do
  b=$(basename "$t" .txt); printf '%-18s ' "$b"
  PYTHONPATH=scripts python3 -m harness.cli check "$t" \
      --records "docs/wsp/verified/records/$b.jsonl" --bars docs/claims-bars.json | sed -n 2p
done
```

`env-check` is the newest piece and it earned its place the hard way: an audit found three documents
asserting things about this host that were no longer true (ncu blocked, no TensorRT, a bundled  <!-- env-ok: describes the past -->
interpreter that does not exist). A claim about the machine is checkable, so it is checked: the tool
reads `/proc` and the installed versions, greps the docs, and fails on a contradiction. A line that
*quotes* an old claim marks itself `<!-- env-ok -->`, and `AUDIT-*` reports are skipped.

`source-check` is the same idea one level up, and it exists because the class-1 failure survived every
gate: from 2026-11-15 to 2026-11-18 the prose called two h264 **4 Mbps re-encodes** "the BD remaster",
and the harness hashed those files faithfully while declaring that a population *label* is not checked.
It is checked now, at least in its mechanical half:

```
PYTHONPATH=scripts python3 -m harness.cli source-check docs/wsp/sources.yaml --clip-root /tmp/opencode
PYTHONPATH=scripts python3 -m harness.cli source-check docs/wsp/sources.yaml --prove   # packet proof
PYTHONPATH=scripts python3 -m harness.cli source-check docs/wsp/sources.yaml \
    --records "docs/wsp/verified/records/*.jsonl"                                      # contaminated records
```

It reads bit rate, packet count, pixel format, colour tags and B-frame depth with `ffprobe`; refuses a
"BD" label below the 35 Mbps floor; proves a `-c copy` cut by locating the clip's video packets as a
contiguous run inside the source (a re-encode has different packet sizes, so no run matches); and lists
every record whose population items name a contaminated input - with a name boundary, because
`bd_violet20s.mkv` CONTAINS `violet20s.mkv`. `docs/wsp/sources.yaml` is the register;
`docs/wsp/verified/sources-bd.txt` is the finding it produced.

What it still cannot check: whether the population is the one a decision needs, and whether a frame
index from one cut names the same picture in another. A short cut also has a scene-dependent container
rate, so the bit-rate floor is not a substitute for the proof.

`harness.migrate` exits non-zero while any decision-bearing finding lacks the tuple. That is the point:
the gate is the debt counter, and it currently reads **0 protected / 211 claims, 62 of them
decision-bearing**.

## The eight classes, and the gate for each

| class | gate |
|---|---|
| a number without its tuple | `Record` refuses to exist without population/instrument/config/session/statistic; relations compare keys, not labels |
| a mechanism named before a discriminating pair | `@cause` needs two records differing in exactly one field |
| leftover from a previous edit → false refusal | A/A before A/B; `refuse()` only against a verified base |
| intent as completion | `run()` waits and kills the group; `probe` is pass/fail/**error**; `ResultsTable` refuses an error row |
| a model of an artifact | parsers with `require()`: "smem" must say static or dynamic, `convs[0]` is read, not recalled |
| a cost model as a measurement | tiers measured/derived/assumed; derived carries formula + inputs and is recomputed |
| one sample as a measurement | `statistic` and the population item-set hash; `below()` compares a bar's `of` and statistic |
| a green check as validation | `Scope.finalize()` refuses green while an expected kind is uncovered; every run prints its own uncovered scope |

## What it does not check, and never will

Whether a population *label* is true; whether the item set is the one the decision needs; whether a cost
model is complete; whether a cited pair rules out the other mechanisms; free-text derivation arithmetic.
The first two are the expensive ones, and they stay human judgements that the harness only makes visible.

## Which file is the reference (the 2026-11-18 mistake, closed by a gate)

A render pair says nothing on its own: the second file IS the instrument's reference, and the numbers differ
by an order of magnitude depending on which one it is.

| reference | what the number means | magnitude on this material |
|---|---|---|
| **the model** (torch fp16 output) | the renderer's own error | **0.004-0.019%** for the int8 body |
| a render of the **fp16 ENGINE** | the pair: engine + colour pipe | **0.42-0.53%** for int8 against it |
| the same renderer, another **configuration** | that configuration's effect | depends on the change |

The engine deviates from the model by 0.055-0.087%, and the colour pipe alone moves **0.21%** of pixels past
the 8-level bar on delivered 4:2:0 material - three to fifty times the quantiser's own error. A comparison
against an engine render therefore cannot answer "how wrong is int8"; it can answer "what does the user see
between these two renders", which is a different, legitimate question.

It is a gate, not a paragraph: `scripts/gate_sweep.py` **refuses to run** without
`--reference-kind {model|engine-render|config}`, prints the declaration in its header, and writes
`extra.reference_kind` + `reference_note` into every record it emits.
`scripts/check_reference_declarations.py` lists any render-pair record in the corpus that does not carry one
(exit 1), and `backend/tests/test_reference_declarations.py` pins both halves on CPU.

```
PYTHONPATH=scripts python3 scripts/check_reference_declarations.py     # the debt list
```
