# Which of the collection's models this pipeline can run

Generated by `scripts/model_fit_report.py` from `model_inventory.py` (what each file IS) and
`model_fit_probe.py` (what happened when the int8 body was built on it). Records:
`docs/wsp/verified/records/model-fit.jsonl`; raw: `logs/model-fit/all.json`.

## The question, and the boundary that answers most of it

`Int8Body` needs a Compact/SRVGG body: **sixteen 64-channel convolutions** between the head and the tail.
That is not a preference - the channel count is a `tl.constexpr` in the Triton kernel, so a model of
another width or another family has nothing for the kernel to replace. Around that core sit four opt-ins
with their own preconditions (head fused: a plain 3->64 head; tail int8: <=16 output channels; shuffle
fold: `nn.PixelShuffle` r=2 with 12 tail channels; tail CSC: needs the fold).

Of **55 distinct model files** in the collection:

| verdict | count | meaning |
|---|---|---|
| **FULL** | 17 | every opt-in applies: int8 hops, int8 tail, shuffle fold, the tail writing the pipe payload |
| BODY+TAIL | 14 | int8 hops and int8 tail; 1x upsamplers, so no shuffle fold and the pack converts colour |
| BODY | 1 | int8 hops only - the tail is wider than the kernel's 16-channel pad (4x models carry 48) |
| **NO** | 23 | RRDBNet / SPAN / OmniSR / RealPLKSR / DAT families, 24-channel compacts, and two files that are not models at all |

## What this says

**Model choice does not buy speed.** The 16 FULL models land at 14.42-28.20 ms for the body - a 50.3% spread that is drift: they are the
same shape (16x64 convs, 12-channel tail), and the sweep ran them one process at a time, so a warm clock
is what separates them. What model choice buys is the picture.

**The gate separates them.** 1 of 22 models read above the app's 1%
start-up gate, i.e. that body would be refused and the fp16 engine would run instead: `1x-Epsilon-one-compact(3).pth` at 1.5394%.
The worst that still passes is `2x_GarfieldJr_net_g_51000.pth` at 0.8763% - inside the 1% gate, but
9 times the 0.1% bar that actually decides a picture, so it would need a
render pair before anyone trusted it.

**The cleanest quantisers are not the model in production.** `2xHFA2kAVCCompact(1).pth`, `2xHFA2k_compact_multijpg(1).pth`, `WoEiCS_2x(1).pth`, `2x-AniScale.pth`, `1x-Dotzilla-Compact.pth`, `1x-AnimeUndeint-Compact(1).pth` read at or below 0.0001% on all three frames, against 0.0114% for Futsuu. That is
a statement about how well each model's activations fit a per-tensor int8 grid, not about which model
upscales better - the fp16 picture is the model, and int8 only decides how much of it survives.

**1x models work but lose the two colour opt-ins.** 14 denoise/restore models run
int8 hops and the int8 tail; their upsampler is not a 2x `PixelShuffle`, so the shuffle fold and the
payload path do not apply and the pack keeps converting colour. The mechanism would generalise (the fold
is exact for any r), but the kernel's `scale == 2` condition is what the shipped code checks - a
deliberate scope line, and the reason a 1x model is not a FULL verdict here.

**4x pays twice.** `realesr-animevideov3` (r=4, 48 tail channels) gets hops only and its body reads
38.04 ms - about a third more than the 2x
models, because the tail stays fp16 and produces 16.6 Mpx instead of 4.1.

## Two grids, and the predictor that failed

`RVE_INT8_PER_CHANNEL=1` makes the int8 grid per channel instead of per tensor. It is not a small
setting: on the same 21 models it rescues some and damages others.

**Rescued** (per-channel at least 3x better): `1x-Epsilon-one-compact(3).pth` 1.5394% -> 0.0979%, `2x_GarfieldJr_net_g_51000.pth` 0.8763% -> 0.0436%, `2x_Ani4K_Compact_35000.pth` 0.3021% -> 0.0140%, `realesr-animevideov3(1).pth` 0.1410% -> 0.0288%, `2x_AniSD_AC_G6i2a_Compact_72500.pth` 0.0982% -> 0.0021%, `1x-BroadcastToStudio_Compact(1).pth` 0.0966% -> 0.0251%, `2x.StarSample.V1.0(2).pth` 0.0650% -> 0.0031%, `2x-anifilm-compact.pth` 0.0600% -> 0.0171%, `2x-sudo-UltraCompact(1).pth` 0.0284% -> 0.0013%, `2x-LD-Anime-Compact.pth` 0.0110% -> 0.0019%.

**Damaged** (per-channel worse by more than half): `2x-Futsuu-Anime(1).pth` 0.0114% -> 0.0309%, `2xken-v1-evA-01.pth` 0.0664% -> 0.1759%, `2xHFA2k_LUDVAE_compact(2).pth` 0.0761% -> 0.2789%.

The hypothesis this row was filed with was that the calibration grid's dynamic range (`max/median` of
the per-channel maxima) predicts which models improve. **It does not.** The two groups overlap:

- rescued models' spreads: [4.2, 4.34, 4.61, 4.74, 4.96, 4.99, 5.15, 6.33, 6.66, 6.93]
- damaged models' spreads: [4.25, 4.48, 4.55]

So the rule is not a threshold on the grid. The implementable version is to **measure both grids and
keep the better one**, choosing on frames disjoint from the ones the start-up gate certifies on -
otherwise the gate would pass by construction. That is a small change, and its cost is one extra
build per render; the alternative (a flag nobody sets) leaves six models looking unquantisable when
the grid was the problem.

## Not covered

- **The fp16 column in the records is eager PyTorch, not the app's TensorRT engine.** It reads ~204 ms
  where the engine reads 52.39 ms (`int8-tail-csc.jsonl` JC001), so the ratios in the records compare the
  BODY ACROSS MODELS. They are not the product's ratio and must not be quoted as one.
- **n=3 frames of one clip.** The gross gate at 1% is a smoke test; the acceptance statistic needs a
  494-frame pair per model, and none of these models has one.
- **No model here was judged on its picture quality.** This page answers "can the pipeline run it and
  does the quantiser survive it", not "does it upscale well" - that is a different lane's question and
  needs the reference frames the model was trained against.
- **A model swap in the product also rebuilds its TensorRT engine** (one engine file per model). That
  cost is outside everything measured here.

## Reproduce

```bash
# what each file IS, from the app's own spandrel loader
<install-python> scripts/model_inventory.py --json docs/wsp/verified/logs/model-fit/inventory.json
# what happened when the body was built on it
flock -n /var/tmp/opencode/gpu.lock <install-python> scripts/model_fit_probe.py \
    --out-file docs/wsp/verified/logs/model-fit/all.json
PYTHONPATH=scripts python3 scripts/model_fit_records.py
PYTHONPATH=scripts python3 scripts/model_fit_report.py
```
