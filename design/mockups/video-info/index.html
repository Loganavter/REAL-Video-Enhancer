Four panels at the panel's real width (460 px), same data as the running render: 1440×1080 → 2880×2160, 24 fps, 493 frames, libx264/mkv, 10-bit bt709; frame 44/493, 9 %, ETA 0:00:23, 19 fps.

Now

Two text dumps: a nine-line list in a plate, and three loose lines under the bar.

A · Transition card

The one fact the panel exists for — what comes out of what — gets the top; the rest is a grid.

B · Spec sheet

Grouped by source/output, values right-aligned on dotted leaders: a column you scan, not a paragraph.

C · Chips

The most compact: one row of facts, the run folded into the transport line. B stays one click away.

What is wrong with the current one

  • Every row has the same weight, so 1440×1080 → 2880×2160 — the reason the panel is there — reads exactly like Container: mkv → mkv.
  • → is doing three jobs at once: "input → output" (a real change), "same on both sides" (noise: mkv → mkv, bt709 → bt709, False → False) and a separator between label and value.
  • The run's numbers (ETA, fps, status) live in a second dump, away from the progress bar they describe; fps is printed twice.
  • Nine rows of prose for six facts: unchanged pairs could collapse to one value, and "HDR: False" is a no-op unless it is true.

What each variant does about it

  • A promotes the resolution change to a headline with the upscale factor as a tag, keeps the technical facts in a two-column grid (label muted, value mono, right-aligned), and moves the run into a card with the bar.
  • B keeps every row but groups them (Source / Output) and aligns the values on leaders; identical values are stated once (bt709 · 10 bit in Source, no second arrow).
  • C is the glanceable reading: chips for the facts, the run on the transport line itself. It assumes a details popover for the rest.
  • A and B both put fps, ETA and status with the bar, and both drop the duplicate fps.

Notes for whoever implements it

  • Values stay ui-monospace with tabular figures: the numbers then line up and stop jittering while the render counts.
  • Every label goes through the catalogue (src/ui/i18n.py) — these mockups are English because the running UI is, and a language switch must rewrite them all.
  • Nothing here needs a new widget: A is a grid of toolkit Text rows + the existing progress bar; B is the same rows with leaders; C is a wrapping row of plates. The 460 px width is the column the page already has.
  • "HDR: no" and "10 bit" are the only rows whose absence would be a lie if dropped — say "off" only when it is a choice, and keep bit depth in the same phrase as the pixel format.
